# Zerolox assembler design experiment

Run `python3 experiments/tobe/assembler/assembler.py experiments/tobe/assembler/example.zlx --object /tmp/example.json` from the repository root. The output lists candidate instruction forms and byte indexes. JSON is the serialized structured object; `assemble()` and `link()` also accept and return Python structures directly.

This is a deliberately incomplete syntax and layout experiment, not an encoder or an emulator image. It supports `!eq`, labels, `!db`, experimental `@align` and `@jumpto`, add, accumulator loads, and a minor branch. `r0` through `r31` are experimental aliases alongside the names in the ISA. Expressions accept literals, size suffixes, `$constant`, `&label`, `#label`, parentheses, `+`, `-`, and `*`. `#` currently measures from the start of the containing instruction; this is a proposal. Strings are ASCII and do not get an automatic terminator. The prototype rejects register-offset addressing because no corresponding form has been implemented.

Layout starts with large instruction sizes, reselects forms, and detects repeated states. It is not a complete relaxation algorithm. Forward references in layout operations and data are not supported yet, and a size-dependent reference that initially appears out of range can be rejected before layout converges. `@jumpto` only moves forward. Neither gaps nor alignment emit bytes here. The minor unconditional branch is the only branch form modeled; no major unconditional branch is assumed. Direct forms use the experimental spelling `m.add r1, r2`, `m.adda r1, r2`, and `m.lda.16 [r1, offset]`.

Pointer size is fixed to three bytes for zerolox one. The prototype has no cross-file linking, external symbols, general target configuration, binary object validation, or machine-code emission. In particular, do not use its listing as an image. The current C emulator accepts a binary image, but encoding and PC-origin behavior need verification before connecting it.
